# 寄件信息强制配置与提示时机设计

## 背景

当前应用在寄件文本框为空时才会校验默认寄件信息配置。寄件文本框有内容时，文本识别和自动识别可以绕过默认配置校验；一键保存也没有寄件信息配置兜底。业务已确认：默认寄件配置是全局必填项，即使寄件文本框已有内容，也必须完成默认配置。

用户未配置时可以继续查看主页面、编辑输入框和查看历史数据，但在执行依赖寄件信息的业务操作时，应提示并引导用户完成配置。

本设计覆盖 `2026-09-29-jd-monthly-text-recognition-sender-priority-design.md` 中“寄件文本框有内容时可不校验默认配置”的旧约束。默认配置完整性从此成为全局业务门禁。

## 目标

1. 默认寄件信息配置始终必填，不受寄件文本框内容影响。
2. 启动时不强制弹窗，配置缺失时通过状态栏提示，并在业务操作被拦截时再次提示。
3. 用户开启自动识别、执行文本识别或一键保存时，统一提示并引导配置。
4. 用户在提示后选择立即配置并保存成功时，继续执行刚才被拦截的操作。
5. 用户取消提示或配置弹窗时，终止当前操作，但仍可继续浏览主页面。
6. 后台剪贴板轮询不弹出模态窗口，避免重复打断用户。

## 非目标

- 不修改寄件文本框解析出的结构化字段优先级。
- 不修改收件人必填字段规则。
- 不自动补全或迁移历史未导出数据中的寄件人字段。
- 不新增独立的配置向导页面。
- 不改变寄件信息配置弹窗中的字段集合。

## 业务规则

默认寄件配置必须满足以下条件：

- 寄件人姓名非空。
- 寄件人地址非空。
- 物品类型非空。
- 寄件人手机、寄件人座机至少填写一项。

温层、流向产品及寄件文本框内容不作为默认配置完整性的替代条件。

配置完整后，文本识别仍沿用现有寄件信息优先级：

1. 当前寄件人组和寄件文本框有效时，使用寄件文本框解析结果。
2. 寄件文本框为空时，使用默认寄件配置。
3. 未选择寄件人组时，使用默认寄件配置。

## 实现设计

### 统一校验

在 `config_manager.py` 中新增 `validate_sender_default_fields(fields)`，作为默认寄件配置的唯一校验入口，返回缺失项提示列表。

`SenderConfigDialog.validate_default_fields()` 改为调用该函数，保持现有弹窗校验行为。

`App` 新增以下内部方法：

- `_sender_config_errors()`：读取 `default_sender` 并返回缺失项列表。
- `_sender_config_ready()`：根据缺失项列表判断配置是否完整。
- `_refresh_sender_config_status()`：配置不完整时更新状态栏。
- `_ensure_sender_config(action_name)`：执行业务操作前的统一门禁。

### 启动行为

主窗口构建并恢复历史数据后调用 `_refresh_sender_config_status()`。

- 无历史数据且配置缺失：状态栏显示“寄件信息未配置，操作前请先配置”。
- 有历史数据且配置缺失：状态栏显示“已恢复 N 条未导出数据；寄件信息未配置，操作前请先配置”。
- 无历史数据且配置完整：状态栏保持空白。
- 有历史数据且配置完整：状态栏仅显示恢复数量。
- 启动阶段不打开配置弹窗。

### 统一操作门禁

`_ensure_sender_config(action_name)` 按以下流程执行：

1. 配置完整时直接返回成功。
2. 配置不完整时更新状态栏，并弹出确认提示，列出具体缺失项。
3. 用户选择取消时返回失败，调用方终止当前操作。
4. 用户选择立即配置时打开现有寄件信息配置弹窗。
5. 弹窗关闭后重新校验；仍不完整则返回失败。
6. 配置完整则返回成功，调用方继续执行原操作。

提示标题固定为“寄件信息未配置”，正文包含当前操作名称，例如：

`使用【自动识别】前需完成寄件信息配置：寄件人姓名、寄件人地址。是否现在配置？`

### 操作路径

自动识别开关：

- 仅在开启自动识别时校验配置。
- 校验失败时开关恢复为关闭状态，不保存开启状态。
- 校验成功或配置保存后，再保存并启用自动识别。
- 为同步开关界面，`AppFrame` 新增不触发回调的 `set_auto_recognize_state(enabled)`。

文本识别：

- 先检查收件人文本是否为空，保持现有“收件人文本为空”状态提示。
- 有文本时调用统一门禁。
- 门禁失败则保留收件人文本，不清空输入框。
- 门禁成功后执行识别并沿用现有清空收件框行为。

一键保存：

- 先检查列表是否有数据和可导出字段。
- 再调用统一门禁。
- 门禁失败时不打开文件选择框、不写入 Excel、不清空列表。
- 门禁成功后继续现有导出流程。

### 后台剪贴板

自动识别开启后，`handle_clipboard_text()` 必须首先校验默认寄件配置，不再判断寄件文本框是否为空。

- 配置完整：继续现有识别入列表流程。
- 配置不完整：更新状态栏并跳过本次识别，不弹出模态窗口。

正常情况下，开启自动识别时已经通过门禁。后台异常分支仅用于配置在运行期间被外部修改或失效的情况。

### 配置保存与取消

配置弹窗保存成功后：

1. 继续由弹窗执行字段校验。
2. 保存配置并刷新 `SenderManager`。
3. 刷新配置状态。
4. 如果本次弹窗来自统一门禁，重新校验通过后继续原操作。

配置弹窗取消后不修改配置，状态栏继续保持配置缺失提示。

## 错误处理

- 配置缺失时不允许生成新的识别数据或导出文件。
- 用户在确认提示中选择取消，不显示额外错误弹窗。
- 配置弹窗校验失败时保持弹窗打开，并显示现有字段级错误。
- 后台剪贴板检测到配置缺失时不中断主线程、不抢占焦点。
- 历史列表数据仍可查看；是否允许导出由当前配置门禁决定。

## 测试设计

1. 共享校验函数覆盖全部必填项和手机/座机二选一规则。
2. 寄件文本框有内容但默认配置不完整时，文本识别仍被阻断。
3. 自动识别开启操作在配置缺失时提示；取消后开关保持关闭。
4. 自动识别开启操作在配置保存成功后继续启用。
5. 文本识别门禁失败时收件人文本不被清空。
6. 一键保存门禁失败时不进入导出写文件流程。
7. 后台剪贴板配置异常时只更新状态，不弹窗。
8. 启动无历史数据时显示配置缺失状态。
9. 启动恢复历史数据时显示恢复数量与配置缺失的组合状态。
10. 配置保存成功后状态栏显示“寄件信息配置已完成”；若随后继续原操作，则由原操作的最终状态覆盖。

## 验收标准

- 未完成默认寄件配置时可以正常查看主页面。
- 任何识别或保存操作都不会在配置缺失时生成结果。
- 用户执行操作时会收到明确、可操作的配置提示。
- 用户取消配置后仍能继续浏览，下一次操作会再次提示。
- 用户保存完整配置后，原操作可以继续执行。
- 后台剪贴板轮询不会因配置缺失反复弹出模态窗口。
