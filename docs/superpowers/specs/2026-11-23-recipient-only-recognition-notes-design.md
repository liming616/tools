# 收件人文本识别与非收件信息归备注设计

## 背景

当前文本识别同时提取收件人字段、商品和备注。识别到姓名、电话或地址时，商品会写入 `items_text`，只有完全无法识别收件人信息时才转入备注。寄件信息配置现已成为全局必填项，物品类型应统一使用默认寄件配置中的内容，不再从收件人文本中推断。

## 目标

1. 点击“文本识别”和自动识别使用相同的收件人字段归类规则。
2. 识别结果只保留收件人姓名、手机、座机、地址以及地址内部组成部分。
3. 商品原文、订单号、配送要求和普通文本统一进入备注。
4. 物品类型始终取 `default_sender.items_text`。
5. 清空识别产生的 `items` 和 `items_text`，避免导出时继续读取识别商品。

## 非目标

- 不修改地址解析器的省、市、区县、道路、楼栋等拆分规则。
- 不修改时效产品、温层、付款方式、重量和件数的现有配置规则。
- 不修改列表单元格编辑和 Excel 字段映射。
- 不迁移历史已生成列表数据。
- 不从普通文本中新增商品、订单号或配送要求的专用字段。

## 字段规则

| 类别 | 字段 | 归属 |
|------|------|------|
| 收件人 | 姓名、手机、座机、完整地址 | 保留在收件人字段 |
| 地址组成 | 省、市、区县、街道、道路、小区、楼栋、单元、房间 | 保留在地址内部字段 |
| 非收件信息 | 商品原文、订单号、配送要求、普通文本 | 合并到 `notes` |
| 物品类型 | `items_text` | 始终取 `default_sender.items_text` |
| 业务默认值 | 时效产品、温层、付款方式、重量、件数 | 沿用现有配置规则，不进入备注 |

地址内部字段属于“收件人地址”的结构化组成部分，不视为额外业务信息。

## 实现设计

### 识别层

在 `recognition.py` 中新增备注合并辅助函数，负责：

1. 接收显式备注、商品原文和未识别文本。
2. 按分号、换行拆分备注片段。
3. 去除 `备注：`、`备注:` 等重复标签。
4. 按规范化后的文本去重并保留首次出现顺序。
5. 使用 `; ` 连接最终备注。

`recognize_line()` 调整为：

- 继续生成姓名、手机、座机、完整地址和地址内部字段。
- 将解析器识别出的商品原文追加到备注。
- 保留解析器已经生成的显式备注和未识别文本。
- 设置 `items` 为空列表。
- 设置 `items_text` 为空字符串。

解析器无需改动商品识别正则。识别层通过备注去重处理同一条款被商品标签和备注标签同时捕获的情况。

### 字段合并层

在 `App._merge_fields()` 合并完识别字段和寄件人字段后执行：

```python
merged["items"] = []
merged["items_text"] = str(
    ((self._config.get("default_sender") or {}).get("items_text") or "")
).strip()
```

该覆盖必须放在最后，确保：

- 识别文本中的商品不能覆盖配置物品类型。
- `items` 中的历史识别结果不会被模板导出优先读取。
- 自动识别和点击文本识别得到一致结果。

## 数据流

```text
收件人原始文本
  -> parse_order_safe / parse_address_safe
  -> 收件人字段 + 地址内部字段
  -> 商品原文 + 显式备注 + 未识别文本
  -> 去重合并为 notes
  -> _merge_fields
  -> items = []
  -> items_text = default_sender.items_text
  -> 列表与导出
```

## 示例

输入：

```text
张三 13800138000 北京市朝阳区xx路1号 苹果x2 周末配送
```

默认寄件配置中的物品类型为“文件”。

输出：

| 字段 | 内容 |
|------|------|
| 收件人姓名 | 张三 |
| 收件人手机 | 13800138000 |
| 收件人地址 | 北京市朝阳区xx路1号 |
| 物品类型 | 文件 |
| 备注 | 苹果x2; 周末配送 |

## 错误处理

- 寄件配置门禁继续在其他业务流程中执行，本设计不改变配置缺失时的提示时机。
- 备注为空时不生成占位内容。
- 相同备注片段只保留一次。
- 商品无法解析为结构化名称时，保留商品原文进入备注，不丢弃原始信息。
- 地址无法解析出省市区时，仍保留完整地址字段。

## 测试设计

1. 识别到收件人时，商品原文进入备注且 `items_text` 为空。
2. 商品和显式备注同时存在时，合并后无重复内容。
3. 无法识别的普通文本继续进入备注。
4. 地址内部字段保持原有解析结果，不进入备注。
5. `_merge_fields()` 使用默认寄件配置覆盖识别商品。
6. `_merge_fields()` 清空识别产生的 `items`。
7. 自动识别与点击文本识别生成相同的物品类型和备注。
8. 配置物品类型为空时保持空值，不从前端文本补回。

## 验收标准

- 收件人区域文本中的商品、订单号、配送要求和其他文本不会进入物品类型字段。
- 物品类型始终显示默认寄件配置中的物品类型。
- 非收件信息在备注中完整、可读且不重复。
- 地址结构化和列表、导出行为保持正常。
- 自动识别和点击文本识别结果一致。
