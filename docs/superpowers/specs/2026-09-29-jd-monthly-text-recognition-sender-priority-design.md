# 京东月结文本识别寄件信息优先级设计

## 背景

京东月结模板执行“文本识别”时，当前寄件信息可能来自当前选中的寄件人组、寄件文本框或默认寄件信息配置。现有实现会在寄件人组字段为空时自动回退默认配置，且缺少统一的完整性校验，导致寄件来源不明确，可能生成缺少寄件人信息的列表数据。

## 目标

仅在京东月结模板点击“文本识别”时，按明确优先级解析寄件信息：

1. 已选择寄件人组且寄件文本框有内容时，以文本框识别结果为准。
2. 已选择寄件人组但寄件文本框为空时，回退使用默认寄件信息配置。
3. 未选择寄件人组时，忽略寄件文本框，仅使用默认寄件信息配置。
4. 需要使用的寄件信息配置不完整时，阻断识别并提示“请配置寄件信息”。

## 非目标

- 不修改自动识别按钮的寄件信息处理流程。
- 不修改京东散单模板及其他模板的文本识别行为。
- 不修改导出流程和现有寄件人组切换行为。
- 不调整寄件信息配置弹窗的字段与校验标准。

## 数据来源

- `selected_sender`：当前选中的寄件人组标签。
- 寄件文本框：`AppFrame.get_sender_text()` 返回的当前单行文本。
- 默认寄件信息：`config.default_sender`。

寄件信息完整性沿用现有配置弹窗标准：

- 寄件人姓名必填。
- 寄件人地址必填。
- 物品类型必填。
- 寄件人手机、寄件人座机至少填写一项。

## 行为规则

| 模板 | 是否选择寄件人组 | 寄件文本框 | 寄件信息来源 |
| --- | --- | --- | --- |
| `JD_MONTHLY` | 是 | 有内容 | 解析并使用文本框内容 |
| `JD_MONTHLY` | 是 | 为空 | 校验并使用默认寄件信息配置 |
| `JD_MONTHLY` | 否 | 有内容 | 忽略文本框，校验并使用默认寄件信息配置 |
| `JD_MONTHLY` | 否 | 为空 | 校验并使用默认寄件信息配置 |
| 其他模板 | 任意 | 任意 | 保持现有行为 |

## 实现设计

### 组件边界

在 `main.App` 中集中增加“文本识别寄件来源解析”逻辑，负责根据模板、寄件人组选择和寄件文本框内容返回寄件字段，或返回表示配置无效的结果。

`_on_recognize()` 保持界面事件入口职责：

1. 检查收件文本框是否为空。
2. 调用寄件来源解析逻辑。
3. 配置无效时弹框并终止。
4. 配置有效时按行识别，合并寄件字段并写入列表。
5. 识别成功后清空收件文本框。

默认寄件信息完整性复用现有 `_sender_config_ready()`，避免新增第二套校验规则。

### 文本框优先规则

仅当以下条件同时成立时，才解析并使用寄件文本框：

- 当前模板为 `JD_MONTHLY`。
- 当前存在非空的寄件人组标签。
- 寄件文本框去除首尾空白后非空。

文本框解析后直接作为本次识别的寄件字段来源，不再与默认寄件信息合并。现有写回当前寄件人档案的行为保持不变。

### 默认配置回退规则

以下情况统一回退默认寄件信息配置：

- 已选择寄件人组，但寄件文本框为空。
- 未选择寄件人组。

回退前必须按统一完整性标准校验 `default_sender`。校验失败时不得识别、不得清空收件文本框，并弹框提示“请配置寄件信息”。

### 错误处理

- 收件文本框为空：维持现有“收件人文本为空”状态提示，不进行寄件信息校验。
- 默认寄件信息配置不完整：显示“请配置寄件信息”，保留用户输入。
- 寄件文本框解析结果为空：文本框非空时仍以文本框结果为准，不自动回退默认配置。

## 测试设计

补充聚焦回归测试，覆盖以下分支：

1. 京东月结、已选寄件人组、寄件文本框有内容：使用文本框解析结果，默认配置不覆盖。
2. 京东月结、已选寄件人组、寄件文本框为空、默认配置完整：使用默认寄件配置。
3. 京东月结、已选寄件人组、寄件文本框为空、默认配置不完整：弹框并阻断，收件文本保留。
4. 京东月结、未选择寄件人组、寄件文本框有内容：忽略文本框并使用默认配置。
5. 京东月结、未选择寄件人组、默认配置不完整：弹框并阻断。
6. 非京东月结模板：保持现有文本识别行为。

测试应验证最终写入列表的寄件字段、弹框内容、收件文本框是否被清空，以及是否创建列表行。

## 验收标准

- 京东月结文本识别严格遵守寄件来源优先级。
- 默认寄件配置缺失时，不产生不完整列表数据。
- 用户文本框输入不会被默认配置覆盖。
- 非京东月结模板行为不变。
